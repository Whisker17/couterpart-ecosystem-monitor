## Affected Modules

- `src/collectors/blog-rss.ts` — RSS feed fetching, parsing, content extraction fallback
- `src/pipeline/stages/analyze.ts` — LLM content analysis with structured output
- `src/pipeline/stages/report.ts` — Daily/weekly report generation
- `src/pipeline/stages/dispatch.ts` — Lark webhook delivery
- `src/pipeline/stages/collect.ts` — Orchestrates collectors per competitor
- `src/storage/db.ts` + `schema.ts` — SQLite initialization, pragmas, migrations
- `src/utils/` — URL normalization, retry, rate-limiter, budget-tracker

## Key Interactions to Verify

### Blog RSS Collector
- Fetch a valid RSS feed and parse items correctly
- Handle truncated RSS content (<500 chars) by triggering article-extractor fallback
- Handle article-extractor failure gracefully (store truncated content, set input_quality='truncated')
- Handle network errors, timeouts, HTTP 403/404 on feed fetch
- Handle malformed XML (invalid RSS feed)
- URL normalization: strip trailing slash, remove utm_ params, force https
- Dedup: skip items with duplicate normalized URLs

### LLM Analyzer
- Analyze content item with full article text — verify structured output matches Zod schema
- Analyze content item with truncated/metadata-only content
- Handle LLM API failure with retry (3 attempts, exponential backoff)
- Handle LLM returning invalid/partial schema
- Skip analysis when monthly budget cap reached
- Track token usage and estimated cost per analysis

### Report Generator
- Build daily report with mixed significance levels (routine/notable/directional_shift)
- Build daily report with zero new content items (empty report)
- Build partial report when some competitors had collection failures
- Build weekly themes on Sunday (cross-competitor pattern analysis)
- Handle too few items for meaningful weekly themes

### Lark Dispatcher
- Successful Lark webhook delivery with message ID tracking
- Retry on Lark webhook failure (3 attempts, 10s intervals)
- Graceful skip when LARK_WEBHOOK_URL is not set
- Handle card exceeding 30KB limit

### Pipeline Integration
- Full pipeline run: collect → analyze → report → dispatch
- Pipeline with partial collector failure (some competitors fail, others succeed)
- Pipeline context carries per-competitor status through all stages
- Pipeline with LLM API failure during analysis (graceful degradation)

### Storage
- Fresh database creation with all tables and pragmas
- Schema migration from older version via user_version pragma
- WAL mode + busy_timeout + production pragmas applied correctly

## Edge Cases

- RSS feed returns valid XML but zero items (new blog with no posts yet)
- Article content is all JavaScript-rendered (extraction returns empty content)
- Competitor blog changes URL structure (old URLs still in DB, new URLs are different articles)
- Multiple pipeline runs in quick succession (busy_timeout prevents SQLITE_BUSY)
- LLM cost tracking accumulates across runs within the same month

## Critical Paths

- Daily pipeline E2E: collect real RSS → analyze with LLM → generate report → deliver to Lark
- Budget enforcement: verify analysis stops when monthly cap is reached
- Partial failure resilience: one competitor's feed fails → other competitors still get analyzed and reported
