## Review Scope

Full architecture review of the approved design doc for Counterpart Ecosystem Monitor — a competitor narrative intelligence pipeline that mirrors the sister project `couterpart-codebase-ecosystem`.

## Issues Found & Resolutions

### Architecture (5 issues)

**1. Content extraction fallback needs DOM library**
- Problem: Design specified `@mozilla/readability` for extracting full article content from truncated RSS feeds, but Bun has no built-in DOM implementation.
- Resolution: Use `@extractus/article-extractor` instead — self-contained, handles fetch + parse + extract in one call, no separate DOM library needed.

**2. Zod schema missing `.describe()` annotations**
- Problem: `ContentAnalysisSchema` fields have no `.describe()` annotations. This is the #1 best practice for Vercel AI SDK `generateObject` — descriptions are sent to the LLM as part of the schema and measurably improve structured output quality.
- Resolution: Add `.describe()` to all 8 Zod schema fields with Chinese-language guidance (e.g., `summary: z.string().describe('1-2句中文摘要，概括竞争对手发布的内容要点')`).

**3. Missing E2E runner for manual pipeline validation**
- Problem: Sister project has `src/e2e-run.ts` as the primary development/validation tool. Design doc didn't specify an equivalent.
- Resolution: Add `src/e2e-run.ts` mirroring sister project — supports `--mode daily/weekly`, `--no-dispatch` for inspecting reports before sending.

**4. URL dedup needs normalization**
- Problem: `UNIQUE(source_url)` constraint uses raw URLs. RSS feeds serve the same article at variant URLs (trailing slash, utm params, http vs https).
- Resolution: Normalize URLs before storing: strip trailing slash, remove tracking params (`utm_*`), force https. ~10 lines in `src/utils/url-normalize.ts`.

**5. Missing `busy_timeout` SQLite pragma**
- Problem: Design lists WAL mode and performance pragmas but omits `busy_timeout`. Without it, concurrent reads/writes (E2E runner during scheduler) get immediate `SQLITE_BUSY` errors.
- Resolution: Add `PRAGMA busy_timeout = 5000` to the pragma suite in `db.ts`.

### Code Quality (1 issue)

**6. Pipeline error propagation between stages**
- Problem: Design says "skip failing sources, mark report as partial" but doesn't specify how partial collection results flow through the pipeline. The analyzer and report stages can't distinguish "no new content" from "collector failed."
- Resolution: Add `PipelineContext` type tracking per-competitor collection status, passed through all 4 stages. Reports accurately show "3/5 competitors collected, 2 failed."

### Test Review (1 issue)

**7. Greenfield project with 0% test coverage**
- Problem: 28 untested codepaths across 6 modules. No test infrastructure exists.
- Resolution: Specify test requirements per module in the design. Test plan written to `docs/reference/test-plan.md`. Tests to be written alongside code during implementation.

### Performance Review

No issues found. Pipeline processes ~5-10 items/day from 5 competitors. LLM calls (~2-5s each) are the bottleneck at <30s total per run.
